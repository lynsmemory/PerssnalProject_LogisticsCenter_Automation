# 개발 진행 및 브랜치 운영 합의

기록일: 2026-10-27

## 현재 상태와 작업 재개 조건

- 현재는 한장기획표를 바탕으로 SRS 초안을 작성하고 검토하는 단계다.
- SRS 작성은 사용자가 진행을 요청했다. 구현, 브랜치 생성, 커밋, 푸시는 별도 진행 요청 전까지 보류한다.
- 조사 결과와 확보한 CAD·URDF는 정리된 상태로 유지한다.

## 저장소 및 브랜치 운영

- 대상 저장소: https://github.com/lynsmemory/PerssnalProject_LogisticsCenter_Automation
- 개발 재개 시 먼저 폴더 구조·핵심 클래스 초안·인터페이스를 정리하고 검토·통합한다. 현재 전체 클래스 구조가 확정된 것은 아니다.
- 이후 관련 클래스를 기능 단위로 묶어 브랜치에서 작업한다. 클래스마다 반드시 별도 브랜치를 만들지는 않는다.
- 기능 브랜치는 통합된 최신 `main`에서 시작하며, 검증 후 `main`에 통합한다.
- 변경 목적이 드러나는 단위로 커밋을 나누고 해당 브랜치로 푸시한다. 이 기록은 지금 푸시하라는 요청이 아니다.

브랜치 이름은 `유형/담당자-작업명` 형식을 사용한다. 예: `feature/LYN-conveyor`. `feat` 같은 축약형은 사용하지 않고, 기능 개발 유형은 `feature`, 담당자는 `LYN`으로 표기한다. 다른 담당자는 해당 담당자 표기를 사용한다.

아래 작업명과 범위는 설계 시 조정 가능한 예시다.

| 브랜치 | 작업 범위 |
|---|---|
| `feature/LYN-project-structure` | 폴더 구조·핵심 클래스 초안·인터페이스 |
| `feature/LYN-conveyor` | 메인 순환 컨베이어·박스 이송 |
| `feature/LYN-qr-sorting` | QR 판독·레인 분류·미인식 반송 |
| `feature/LYN-gravity-lane` | 중력 롤러·대기열·스토퍼 |
| `feature/LYN-robot-palletizing` | FR5·흡착·ML 위치 인식·적재 |
| `feature/LYN-amr-loading` | AMR 파레트 운반·차량 상차 |
| `feature/LYN-dashboard` | 생산속도 제어·상태·병목 표시 |

## 다른 PC에서 대화 이어가기

- Git과 별도로 대화 인계용 Markdown 문서를 개인 클라우드나 USB로 전달하는 방식으로 합의했다.
- 문서에는 확정 조건, 한장기획표 검토 상태, 조사 자료·CAD 출처와 확보 상태, 미결정 사항, 다음 작업 및 보류 지침을 포함한다.
- 인계 문서는 저장소 밖에 보관하며 Git에 올리지 않는다. 이 파일 자체는 전체 대화 인계 문서를 대신하지 않는 로컬 합의 기록이다.
- CAD·URDF 등 실제 파일은 대화 맥락과 별도로 전달해야 한다.

## SRS 작성 추가 합의

- 문서에는 가운데점을 쓰지 않는다. 추상적인 표현 대신 박스와 설비의 실제 동작을 짧은 문장으로 적는다.
- 각 층을 모두 채운 뒤 다음 층을 쌓는다. 높이가 다른 기둥을 만드는 14개 안은 제외한다.
- 검토한 가상 셀의 형상과 경로 검사를 통과한 360×280×340mm, 질량 2kg, 층당 6개, 3단 18개, FR5 베이스 900mm를 SRS v0.1에 반영했다. 실장비와 전체 Unity 씬 검증을 끝냈다는 뜻은 아니다.
- 바코드는 Code 128이며 L01, L02, L03은 각각 1번, 2번, 3번 레인이다. 미판독 오류 처리는 MVP에서 제외한다.
- 성능과 인식 정확도의 목표 수치는 미정으로 두고 구현 후 측정해 결정한다.

## Schmalz 실제 CAD 검사 추가 기록

- Docs/CAD의 실제 4컵 조립 CAD에서는 플랜지부터 비압축 흡착면까지 182.8mm다. 이전 125mm 단순 툴과 다르다.
- 베이스 900mm에서 3단의 정지 적재점은 닿지만, 이번에 검사한 두 운반 경로는 18개 완료에 실패했다. 따라서 이전 단순 툴 검사를 실제 제품의 3단 검증으로 사용하지 않는다.
- 비교한 베이스 950mm 안은 층당 6개씩 3단 18개의 운반 및 빈 툴 복귀 샘플 검사를 통과했다. 실제 흡착 유지와 손목 하중, 케이블 및 전체 셀 검증은 남아 있다.
- 950mm는 비교 제안이며 사용자 결정 없이 SRS의 설치 높이를 변경하지 않았다. 상세 결과는 FR5_CAD_Validation/README.md에 있다.

## SRS 공정 조건 추가 확정

- 메인 컨베이어는 상시 운전하는 순환형이다. 레인 정체가 생겨도 메인을 멈추지 않는다. 이번 사용자 확인으로 순환 대기를 SRS 범위에 반영했다.
- 목적 레인별 순환 대기는 최대 3개다. 분기하지 못한 박스는 메인을 순환하다가 롤러 중간 스토퍼 앞이 비면 해당 레인으로 분기한다.
- 롤러 중간 스토퍼 앞에는 1개만 대기한다. FR5 취급 중에는 스토퍼를 닫아 픽업 구역 진입을 막는다. 다음 픽업이 가능할 때 1개를 내려보내고 다시 닫는다. 순환 대기 3개, 스토퍼 앞 1개, 픽업 구역 또는 FR5 취급 중 1개로 목적 레인별 총 5개를 관리한다.
- 완성 파레트를 AMR이 반출하면 기존 위치에 빈 파레트를 재생성한다. 별도 공급 공정은 없다.
- AMR은 레인별 전담이며 적재 완료 신호 수신 후 이동한다. 장애물 발견 시 정지한다. 상차 실패는 자체 재시도하며 횟수와 간격, 반복 실패 후 처리와 다른 실패 처리는 시험 후 정한다.
- 시작, 일시정지, 재개, 초기화, 생산속도 조절을 모두 제공한다. 처리한 제품과 시간당 생산량 등 모니터 표시값을 기록한다. 파일 형식과 저장 주기, 보관 기간은 아직 정하지 않았다.
- 투입 간격과 생산속도 범위는 시뮬레이션 측정 후 정한다.
- 사용자 편집본에 관련 요구사항과 시험 항목만 반영했다. 조작 기능 FR-21, 화면 UI-04, 시험 TC-28을 추가했다. 구현과 Git 작업은 계속 보류한다.

## 검토 피드백 채택

- 현재 사용자 편집본은 Docs/SRS_LogisticsCenter_v1.0.docx다. 해당 파일에 관련 내용만 반영했으며 기존 사용자 수정사항을 보존했다.
- ML-Agents 계획을 CNN 이미지 인식으로 변경했다. Unity 합성 이미지 수집, CNN 학습, ONNX 모델의 Unity Sentis(Inference Engine) 추론을 선택 확장으로 둔다. 11/3 MVP와 11/5 발표 일정은 유지하고 CNN은 11/4 통합 시험 후 여유 시 적용한다.
- FR-20과 TC-20을 삭제하고 다른 번호는 유지했다. FR-22는 픽업 끝 스토퍼와 측면 가이드, FR-23은 건물과 구역 배치, FR-24는 전체 및 분류, FR5, 도크 뷰 전환, FR-25는 기본값과 시연값 분리다. TC-29~TC-32를 추가했다.
- 중간 스토퍼와 픽업 끝 스토퍼는 별개다. CNN 미적용 상태에서도 끝 스토퍼와 측면 가이드로 기본 공정을 실행한다. 새 정렬 장치의 형상은 이전 CAD 검사에 없으므로 Unity 배치 후 간섭을 확인한다.
- 목적 레인별 순환 대기 3개에서 정체를 설정하고 해당 바코드 새 박스 투입을 중지하며 알람을 표시한다. 정체 후 대기 2개는 유지, 1개 이하에서 해제한다. 기존 순환 박스는 스토퍼 앞이 비면 계속 분기하므로 대기 수가 줄어들 수 있다. 메인 컨베이어는 계속 운전한다.
- 레인 i, AMR i, 도크 i의 현재 차량을 전담 연결한다. i는 1, 2, 3이며 차량 교체 후에도 연결을 유지한다.
- 기본 설정은 층당 6개씩 3층 18개, 차량당 10파레트다. 시연 설정은 층당 6개씩 2층 12개, 차량당 3파레트다. 각 층을 다 채운 뒤 다음 층으로 진행하는 조건은 유지한다. 본문의 적재 완료와 만재 시험은 선택한 층 수 L과 만재 수량 N을 사용한다. 기존 3층 CAD 검증 기록은 보존한다.
- WBS와 구현, 브랜치 생성, 커밋, 푸시는 아직 시작하지 않았다.
