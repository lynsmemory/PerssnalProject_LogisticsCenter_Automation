# 2026년 10월 28일 작업 분석과 클래스 분류안

오늘의 WBS 목표는 씬 배치 9건이다. 사용자 요청에 따라 클래스 분류와 스크립트 설계를 선행 작업으로 추가한다. 아래 클래스 이름과 API는 구현 제안이며 기존 구현이나 확정 요구사항으로 취급하지 않는다.

## 검토 기준

- 일정: `../WBS_LogisticsCenter.xlsx`, 프로젝트WBS 시트의 계획 시작일·완료일과 작업 완료율.
- 기능·수치·시험: `../SRS_LogisticsCenter_v1.1.docx`, 3장·6장·7장.
- 공정 의도: `../LYN_프로젝트_한장기획표.pptx`, 슬라이드 1.
- 코드 참고: 상위 Unity 폴더의 `Cell_Factory-main/Assets/Scripts/Factory`.
- 현재 프로젝트: Assets의 C# 파일 목록, 컨베이어 제공 스크립트, Packages/manifest.json 확인. Unity 실행이나 기능 시험은 수행하지 않았다.

기획표에는 색상 판별·센서 속성 판독, 11/1 ML 연결과 11/2 전환 일정이 남아 있다. 구체적인 구현은 SRS v1.1과 WBS에 맞춰 Code 128 이미지 판독, CNN 없이 기본 공정 구현, 11/4 통합 시험 후 여유 시 CNN 적용으로 정리한다. Research의 과거 수정 문안에는 QR·오류 반송·AMR 1대 등 이전 내용이 있어 현재 설계 기준으로 사용하지 않는다.

FR-01은 주로 씬·Prefab·구역 배치 작업이며 전용 런타임 클래스를 의무적으로 만들 필요는 없다. FR-08의 경사 롤러에도 강제 이송 클래스를 의무적으로 두지 않는다. 중력과 Collider·마찰로 시험하고, 롤러 회전 표현이 필요하면 별도 시각화 컴포넌트만 추가한다.

## 먼저 정할 상태와 인계 규칙

1. `LaneId`를 L01/L02/L03 판독 결과와 연결한다. BoxInfo의 설정 목적지를 판독 성공으로 대체하지 않는다.
2. 레인별 집계는 순환 대기 3개, 중간 스토퍼 앞 1개, 픽업 또는 FR5 취급 1개다. 픽업→흡착 전이에서 같은 박스를 두 번 세지 않는다.
3. 분기 직후 경사 이동 중인 박스도 예약/이동 상태로 관리해 동시 진입과 집계 누락을 막는다. 세부 센서 경계는 씬 배치 후 결정한다.
4. 정체는 순환 대기 3개에서 설정, 2개에서 유지, 1개 이하에서 해제한다. 신규 투입 제한과 기존 박스 분기 허용은 별도 판단이다.
5. FR5가 박스를 들었더라도 로봇과 박스가 픽업 영역에서 벗어나기 전에는 다음 박스를 방출하지 않는다.
6. 적재 슬롯은 예약과 완료를 구분한다. 해제·배치 성공 확인 뒤 완료 처리하며 실패 시 층·개수를 증가시키지 않는다.
7. 파레트 완료 신호는 전담 AMR에 한 번 전달한다. 인양 시작이 아닌 실제 반출 확인 뒤 빈 파레트를 생성한다.
8. 차량 적재 성공 확인 뒤 파레트 ID별 한 번만 개수를 증가시킨다. N개에서 출발하며 차량 교체 뒤에도 LaneContext의 도크 연결을 유지한다.
9. 공정 일시정지는 전체 조작이고 레인 정체는 국소 상태다. 레인 알람 때문에 메인 컨베이어를 정지시키지 않는다.

## FR5 URDF 준비 결과

- 공식 출처: https://github.com/FAIR-INNOVATION/frcobot_ros2
- 모델: SRS와 기존 CAD 검증에서 사용한 `fairino5_v6`.
- 기준 커밋: `867cb32bc24a73c1e60bef4e6c16762e7357c5e1`.
- 로컬 URDF: `CAD_References/FR5/fairino_description/urdf/fairino5_v6.urdf`.
- 연결 메시: `CAD_References/FR5/fairino_description/meshes/fairino5_v6`의 STL 7개.
- 10/28 공식 커밋의 URDF를 다시 다운로드하고 기존 manifest SHA-256과 일치 확인했다. 파일 크기는 10,173 bytes다.
- 기존 URDF·package.xml·STL 총 9개 파일의 SHA-256, 모든 mesh 참조 경로, 바이너리 STL 7개의 길이와 삼각형 개수 일치를 확인했다.
- URDF SHA-256: `bf875243b954bba414a6fba876272e78deee8defbfa0cfc26b82f6d586bacb9e`.
- 원본 package 경로를 유지했다. 다운로드 및 파일 검사 완료는 Unity 임포트·Prefab 생성·관절 동작·충돌 시험 완료를 의미하지 않는다.

WBS 13행은 FR5 Import 완료로 기록되어 있지만 현재 Assets의 파일 목록에서는 FR5 URDF/Prefab을 확인하지 못했다. Docs 원본 확보와 Unity 반영 상태를 구분해 재확인할 필요가 있다. 현재 manifest에는 URDF Importer가 없다. 사용할 임포트 방식과 FR5 실제 관절 구성을 확인한 뒤 IK 연결을 진행한다.
