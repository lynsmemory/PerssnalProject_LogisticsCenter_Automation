# 차량 외형 재제작 요청

사용자는 기존 기본 도형 차량의 디자인을 거부했고 첨부 사진을 참고해 다시 제작하도록 지시했다. 이 요청은 차량 에셋 제작용 스크립트에 대한 착수 승인이다. 공정 런타임 스크립트 작성 보류는 유지한다.

## 역할과 범위

Claude는 제작 스크립트만 작성한다. Codex가 실행해 메시·Prefab·재질을 생성하고 결과를 검수한다. Claude는 기존 씬, Prefab, 원본 생성기, AGENTS.md, CLAUDE.md를 직접 수정하지 않는다. 코드는 `Docs/Research/rebuild_wingbody_detailed.py` 하나로 작성하고 검증 결과 및 실행법을 `Docs/Collaboration/Truck_Visual_Redesign_Result.md`에 기록한다. 사용자 제공 참조 이미지 2개를 Read로 직접 보고 외형을 설계한다.

## 결과물 기준

- 원래 차량은 큐브 운전석과 원통 바퀴라 실차 비율과 형태가 부족하다. 이번에는 큐브 장식 추가에 그치지 말고 운전석 주요 형상을 실제 메시로 만든다. 사진의 한국형 중형 캡오버 5톤 윙바디 인상을 우선한다. 특정 제조사의 정확한 CAD 복제라고 표기하지 않는다.
- 전체 전장 약 8.7~9.2m, 전폭 약 2.4m. 적재함 내부 길이 6.2m, 폭 2.3m, 높이 2.4m. 전방 +Z, 위 +Y, 단위 m.
- CargoFloor 상면은 로컬 Y=1.1m를 유지한다. 씬의 차량 루트 Y=-1.08976m이므로 공장 바닥 Y=0.01024m와 일치해야 한다.
- 기존 차량 Prefab GUID ec8a971b886b75927171a490e1a5b544와 루트 GameObject fileID=10, Transform fileID=11을 유지한다.
- 반드시 보존할 피벗 Transform fileID: LeftWingPivot=61, RightWingPivot=271, RearDoorLeftPivot=231, RearDoorRightPivot=441. 기존 씬은 이 ID를 override해 뒤 문만 좌/우 180/-180도로 열고 양쪽 윙은 0도로 닫아둔다. 루트 및 피벗의 위치/축과 의미도 유지한다. 필요하면 문/윙 형상은 그 아래 새 자식으로 만든다.
- 기존 파레트 슬롯 10개, 도크 기준점, 접근 기준점은 이름·좌표·fileID를 유지한다. 기존 prefab에서 읽어 필요한 기준 노드를 보존한다.
- 양쪽 윙과 운전석 문에 쿠팡 로고. 기존 Textures/CoupangSide.png 재활용 가능. 브랜드는 사용자가 제공한 사진 기반 근사본임을 기록한다.

## 외형 우선순위

1. 운전석: 정면 하부와 A필러/앞유리에 경사, 모서리 챔퍼, 루프·전면 루프 페어링. 앞유리는 실제 표면에 붙이고 양옆 앞유리 모서리와 측창을 분리한다. 무거운 직육면체 하나처럼 보이지 않아야 한다.
2. 앞바퀴 휠 아치: 타이어 영역을 차체가 덮지 않도록 운전석 측면 메시 자체에 아치 형태를 만든다. 휠 아치만 검은 반원으로 그려 큐브 위에 덧붙이는 방식은 부족하다.
3. 바퀴: 24~32분할 이상 타이어 프로파일과 림, 중앙 허브·볼트·홀. 뒷바퀴와 흙받이, 앞뒤 휠베이스가 사진 비율과 맞아야 한다.
4. 전면: 검은 다단 그릴, 헤드램프 분리, 전면/하부 범퍼, 와이퍼·도어 손잡이·미러 암·계단. 전면은 +Z에서 보인다.
5. 적재함: 흰색 매끈한 패널, 은색 테두리, 하부 금속 띠, 잠금 핸들/힌지/주황색 반사판, 후면 프레임과 램프. 로고는 패널 위에 읽기 좋은 크기로 배치하고 부재에 가리지 않는다.
6. 하부: 프레임 레일·횡보·연료탱크·측면 언더가드·차축. 도크 높이에서 하부가 감춰지더라도 모델 자체는 일관된 구조를 가진다.

## 파일 제작과 검증

- 번들 Python: C:/Users/LYN/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/python.exe. Pillow 사용 가능. 시스템 패키지나 pip 설치 금지.
- 외형은 OBJ 메시 파일과 URP Lit 재질, Unity native prefab으로 만든다. 네트워크/다운로드/Blender 설치는 이번 스크립트 범위 밖이다. 메시마다 단순한 OBJ asset으로 가져오면 fileID 참조를 추측하지 않도록 Unity Mesh를 직접 YAML `.asset`으로 저장하는 방법도 검토하라. Unity 기본 primitive만 사용한 운전석은 허용하지 않는다.
- 메시를 Unity `.asset`으로 작성할 때는 현재 프로젝트에서 실제 직렬화 예시를 먼저 찾고 검증하라. 지원 구조를 확신할 수 없다면 OBJ와 Unity가 생성할 main mesh fileID=4300000 사용 여부를 명확히 기록해 Codex가 검수할 수 있게 하라.
- 생성기는 `--output` 같은 인자를 받아 별도 임시 폴더에 먼저 생성할 수 있어야 한다. 생성 이후 검수 통과 전 원본 Prefab 교체를 하지 않는 모드가 필요하다.
- 앞/옆/사선 세 방향의 소프트웨어 메시 프리뷰 PNG를 Pillow로 생성해 Codex가 형상·비율을 검수할 수 있게 한다. 프리뷰는 실제로 생성한 메시와 동일한 정점·면·재질 데이터를 투영해야 한다. 일러스트로 그럴듯하게 대신 그리지 않는다. 텍스처 로고는 프리뷰에서 UV 투영하거나 생략 여부를 명시한다.
- 정점/면 인덱스 유효성, 법선 방향, 바닥 상면, 피벗 ID, 씬 참조, 중복 ID와 생성 파일 수를 검증해 JSON으로 기록한다. Unity 임포트나 화면 확인을 하지 않았으면 완료라고 쓰지 않는다.
- 사용자에게 직접 최종 보고하지 말고 Codex 검수를 위한 결과 문서와 짧은 요약만 남긴다.
